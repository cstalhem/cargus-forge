- Read only this plugin's files, the current repo's files, and GitHub data about the current repo, such as issues, PRs or branch protection. Read `docs/adr/` and `docs/agents/` only if they exist.
- Read GitHub data only with `gh api` REST calls that change nothing, on every surface. Write each path in full as `repos/{owner}/{repo}/<path>`, for example `gh api repos/{owner}/{repo}/issues/<n>`. `gh api` fills in `{owner}` and `{repo}` for the current repo. Quote a path that holds `?` or `&`, and add `--paginate` to a list. A 404 from `issues/<n>/parent` means the issue has no parent. Do not read issue or PR data with `gh issue` or `gh pr` commands, other than `gh pr diff` and ship's `gh pr checks --watch`.
- Add no labels.
- Write to GitHub only with `gh api` REST calls, on every surface, with each path written in full as for reads. Create an issue with `-X POST repos/{owner}/{repo}/issues`, rewrite one with `-X PATCH repos/{owner}/{repo}/issues/<n>`, post a comment on an issue or a PR with `-X POST repos/{owner}/{repo}/issues/<n>/comments`, and open a PR with `-X POST repos/{owner}/{repo}/pulls`. Pass a text field with `-f <field>=<value>`, and a number or a boolean with `-F`, such as `-F draft=true`. Other than `gh pr ready` and creating a branch as the next rule says, do not write with `gh issue` or `gh pr` commands, or with any tool other than `gh api`.
- Create a branch with `gh issue develop <n> --base <base> --name <n>-<slug>`, so it is linked to its issue. If that gets a GraphQL 403, run `git fetch origin <base>`, then `git push origin <sha>:refs/heads/<n>-<slug>`, with `origin/<base>` as `<sha>`. That branch has no link, because no REST route links a branch to an issue. Do not create a branch with `POST git/refs`, which the cloud proxy refuses. Either way, read the branch back with `gh api repos/{owner}/{repo}/branches/<n>-<slug>`.
- Pass every issue body, PR body and comment as `-F body=@<path>`. First write the text with the Write tool to a new file in the session's scratchpad directory, else in the system temp directory (`$TMPDIR`, else `/tmp`). Never use a heredoc: Claude Code's worktree guard refuses one whose text mentions git.
- After each write to GitHub, read the result back with `gh api` REST, for example `repos/{owner}/{repo}/issues/<n>/parent` for a sub-issue's parent, `repos/{owner}/{repo}/issues/<n>/dependencies/blocked_by` for a blocked-by link, `repos/{owner}/{repo}/pulls/<n>` for a PR's base and draft state, `repos/{owner}/{repo}/issues/<n>/comments` for a posted comment, and `repos/{owner}/{repo}/branches/<branch>` for a created branch. If a fact the step needs is missing, stop and name it.
- In a Claude Code cloud session, each issue, PR and comment body written through REST gets a `---` line and a `_Generated by …_` footer at its end. That footer is not part of the body's last section: ignore it when you read a body, and compare a read-back without it.
