Engineering Workflow Plugin for Cargus Forge

Why · 6 requests I want to build out my own plugin for Engineering with Claude and AI. It should consist of Skills, templates, and any other small bits and bobs that are relevant for this discipline What I like about it is that it's opinionated about a order of operations (Discuss, Plan, Execute, Verify, Ship) … I also like the idea of state surviving between sessions What I am hesitant, or worried, about is context bloat. Especially GSD feels like it's very fond of writing to a lot of files and keeping them in a lot of places. I would really like to be able to get plan files or artifacts that I can open on my phone or other computer when I work from them. The process should also be helpful in highlighting for me which both my known and unknown unknowns are … It's also very important that it's a continuously improving process I'd also like to talk through and implement this project in stages so that it becomes manageable to implement.

The size of the work selects the path through the process.

When does the research phase run?
Cost GSD path measured 8.7 times the tokens of direct work on a small task. A research pass on every bug moves us toward that number.

The long path has seven phases. Each phase has one exit gate.

The agent finds the facts. You make the decisions.

Each discussion ends with your known and unknown unknowns.

The agent names them. You decide if they matter.

A separate agent grades the work against the goal, not the summary.

Each phase hands work to the next through GitHub or the repo.

Where does the state between sessions live?
Change Claims 2.1 and 2.3 change. The plugin must then keep files and issues the same.

The umbrella issue holds the goal, the scenarios and the decisions.

Each scenario becomes a test or an eval case.

Each sub-issue fits one session and names one verify command.

The command must fail before the work and pass after it.

The /next command tells you where you stopped, on any device.

Plans are disposable. ADRs, the glossary and the tests stay.

You read and answer each plan on your phone.

A tap goes to the next open decision.

How does the plugin make HTML plans?
Setup marketplace.json must allow the claude-plugins-community marketplace as a source of dependencies.

Plans, issues and ADRs use STE at approximately 80 percent.

The limit for an instruction is 20 words.

Your answers come back to the session as one structured response.

Remote Control sessions on the Linux host can publish the page.

Limit Mods draw only in the local terminal. The phone never shows them, so this plugin does not use them.

The plugin loads only the instructions that the current phase needs.

What happens to knowledge-system and adr-management?

Skills that you type cost no context until you call them.

The plugin stays near 1,500 lines of instructions in total.

Evidence GSD core loads 35,000 to 40,000 tokens before its plan phase starts. We measure each skill with claude plugin eval.
